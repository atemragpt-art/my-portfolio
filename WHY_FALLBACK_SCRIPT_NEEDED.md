# 🤔 Почему потребовался скрипт для создания страниц-заглушек?

## 📋 Краткий ответ

**Astro i18n fallback работает только для существующих страниц.** Если страница физически не существует в файловой системе, Astro возвращает 404 **до** применения fallback. Поэтому нужны страницы-заглушки, которые явно обрабатывают редирект.

---

## 🔍 Детальное объяснение

### Как работает Astro i18n fallback

Astro i18n fallback (`i18n.routing.fallback`) работает следующим образом:

1. **Пользователь запрашивает:** `/de/expertise/`
2. **Astro проверяет:** Существует ли файл `src/pages/de/expertise/index.astro`?
3. **Если файл существует:**
   - Astro загружает страницу
   - Если контент не найден (например, в Content Collections), применяется fallback
   - Пользователь видит контент fallback языка или редирект (в зависимости от `fallbackType`)
4. **Если файл НЕ существует:**
   - Astro возвращает 404 **сразу**
   - Fallback **не применяется**, потому что роутинг не знает о существовании этого маршрута

### Проблема: Fallback не работает для несуществующих маршрутов

```javascript
// astro.config.mjs
i18n: {
  locales: ['ru', 'en', 'de', 'es', 'fr', 'pt', 'it', 'tr', 'ar', 'zh'],
  routing: {
    fallback: {
      de: 'en',  // Fallback настроен
      es: 'en',
      // ...
    },
    fallbackType: 'redirect',
  },
}
```

**Ожидание:** При запросе `/de/expertise/` Astro должен автоматически редиректить на `/en/expertise/`.

**Реальность:** Astro возвращает 404, потому что файл `src/pages/de/expertise/index.astro` не существует.

### Почему Astro так работает?

Это архитектурное решение Astro:

1. **Производительность:** Astro не сканирует все возможные маршруты при каждом запросе — это было бы слишком медленно.
2. **Явность:** Astro следует принципу "explicit is better than implicit" — если страницы нет, значит её нет.
3. **Статическая генерация:** В режиме `output: 'static'` Astro должен знать все маршруты на этапе сборки. Несуществующие маршруты не могут быть предварительно обработаны.

### Что делает fallback в Astro?

Fallback в Astro работает только в следующих случаях:

1. **Страница существует, но контент отсутствует:**
   ```astro
   <!-- src/pages/de/expertise/index.astro существует -->
   ---
   const items = await getCollection('expertise', ({ data }) => data.lang === 'de');
   // Если items пустой, fallback может показать английский контент
   ---
   ```

2. **Страница существует, но использует fallback для контента:**
   ```astro
   <!-- Страница существует, но показывает контент fallback языка -->
   ---
   const lang = 'de';
   const fallbackLang = 'en';
   const content = await getContent(lang) || await getContent(fallbackLang);
   ---
   ```

**Fallback НЕ работает, если:**
- Файл страницы не существует в файловой системе
- Маршрут не зарегистрирован в роутинге Astro

## 🛠️ Решения и их ограничения

### Вариант 1: Использовать только существующие языки (рекомендуется Astro)

```javascript
// astro.config.mjs
i18n: {
  locales: ['ru', 'en'], // Только языки с существующими страницами
}
```

**Плюсы:**
- ✅ Простота
- ✅ Нет лишних файлов
- ✅ Явная структура

**Минусы:**
- ❌ При переходе на `/de/about` будет 404
- ❌ Нужно создавать все страницы сразу для всех языков
- ❌ Нельзя использовать переводы UI для языков без страниц

### Вариант 2: Страницы-заглушки (наш подход)

```astro
<!-- src/pages/de/expertise/index.astro -->
---
import { getLocalizedPath } from '@/i18n/utils';
return Astro.redirect(getLocalizedPath('/expertise/', 'en'), 307);
---
```

**Плюсы:**
- ✅ Fallback работает корректно
- ✅ Можно использовать переводы UI для всех языков
- ✅ Постепенное добавление реальных страниц
- ✅ Нет 404 ошибок

**Минусы:**
- ❌ Нужно создавать много файлов вручную
- ❌ Дублирование структуры (но это временно)

### Вариант 3: Middleware с обработкой 404

```typescript
// src/middleware.ts
export const onRequest = defineMiddleware(async (context, next) => {
  const response = await next();
  
  if (response.status === 404) {
    const lang = getLangFromUrl(context.url);
    const fallbackLang = getFallbackLang(lang);
    
    if (lang !== fallbackLang) {
      return Astro.redirect(getLocalizedPath(context.url.pathname, fallbackLang), 307);
    }
  }
  
  return response;
});
```

**Проблема:** В Astro middleware не может перехватить 404 до того, как ответ будет отправлен клиенту. Astro обрабатывает 404 на уровне роутинга, до middleware.

**Почему не работает:**
- Astro роутинг обрабатывает 404 **до** middleware
- Middleware получает уже готовый 404 ответ
- Невозможно изменить статус ответа после того, как он создан

### Вариант 4: Использовать `fallbackType: 'rewrite'`

```javascript
i18n: {
  routing: {
    fallbackType: 'rewrite', // Показывает контент без изменения URL
  },
}
```

**Проблема:** Это работает только если страница существует. Если файла нет, всё равно будет 404.

## 🎯 Почему нужен скрипт?

### Без скрипта нужно создать вручную:

- **8 языков** с fallback (de, es, fr, pt, it, tr, ar, zh)
- **11 путей** для каждого языка:
  - Статические: about, contact, faq, hr, privacy, terms
  - Со списками: blog, cases, expertise, industries, solutions
  - Главная: index
- **2 файла** для каждого пути со списками (index.astro + [...slug].astro)

**Итого:** ~8 × (6 статических + 5 списков × 2 файла + 1 главная) = **~136 файлов**

### Со скриптом:

```bash
bash scripts/create-fallback-pages.sh
```

**Результат:** Все файлы созданы автоматически за несколько секунд.

## ✅ Вывод

**Astro i18n fallback работает только для существующих страниц.** Для несуществующих маршрутов нужно создавать страницы-заглушки вручную или через скрипт. Это не баг, а архитектурное решение Astro для производительности и явности.

**Скрипт нужен потому что:**
1. Fallback не работает для несуществующих файлов
2. Middleware не может перехватить 404
3. Вручную создавать ~136 файлов неэффективно
4. Скрипт автоматизирует рутинную работу

**Альтернатива:** Использовать только языки с существующими страницами, но тогда нельзя использовать переводы UI для других языков и будут 404 ошибки.
